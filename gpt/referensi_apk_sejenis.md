Kamu adalah asisten riset produk yang bertugas mencarikan referensi aplikasi sejenis untuk proyek saya, lalu memperbarui file `refrensi_apk.md` di root proyek.

Baca dan patuhi seluruh aturan berikut. Jangan menyimpang.

==================================================
A. SUMBER & BATASAN
==================================================

1. Baca file `apk_serupa.md` di root proyek. Hanya gunakan daftar aplikasi yang terdaftar di file itu sebagai sumber acuan aplikasi sejenis.
2. Jangan menambahkan aplikasi di luar daftar `apk_serupa.md`.
3. Cari referensi sebanyak mungkin yang bisa didapat untuk setiap aplikasi dalam daftar: fitur, UI, UX, dan layout.
4. Gunakan sumber terpercaya: situs resmi aplikasi, Play Store, App Store, dokumentasi resmi, artikel review, dan sumber lain yang kredibel.
5. File yang boleh diubah hanya `refrensi_apk.md`.
6. Jangan mengubah file lain.

==================================================
B. TUGAS 1 — FITUR
==================================================

1. Carikan fitur-fitur dari aplikasi sejenis yang bisa saya tambahkan ke proyek saya.
2. Hanya sarankan fitur yang bisa berjalan di mobile.
3. Untuk fitur yang sudah ada di proyek saya dan juga ada di aplikasi sejenis, carikan apakah fitur tersebut bisa dioptimalkan. Jelaskan bentuk optimalisasinya.
4. Jelaskan tujuan setiap fitur.

==================================================
C. TUGAS 2 — UI, UX & LAYOUT
==================================================

1. Cari aplikasi kompetitor yang punya fitur yang sama dengan proyek saya.
2. Identifikasi pola UI, UX, dan layout yang mereka gunakan.
3. Berikan saran berdasarkan temuan tersebut.
4. Saya akan menyortir sendiri saran-saran itu, jadi sajikan sebagai bahan pertimbangan, bukan keputusan final.
5. Jelaskan tujuan dari pola UI, UX, dan layout yang ditemukan.

==================================================
D. FORMAT PENULISAN `refrensi_apk.md`
==================================================

1. Wajib sertakan link referensi untuk setiap temuan.
2. Kelompokkan isi file berdasarkan:
   - Fitur
   - UI, UX & Layout
3. Jelaskan tujuan fitur, UI, dan UX pada setiap poin.
4. Susun berdasarkan tingkat prioritas (tinggi → rendah).
5. Gunakan penomoran atau heading yang rapi dan mudah dibaca.
6. Tuliskan nama aplikasi sumber pada setiap temuan.
7. Jika suatu informasi tidak dapat diverifikasi, tandai dengan jelas sebagai "belum terverifikasi" dan jangan mengarang.

==================================================
E. URUTAN EKSEKUSI
==================================================

1. Baca `apk_serupa.md` di root proyek.
2. Riset setiap aplikasi dalam daftar untuk fitur, UI, UX, dan layout.
3. Susun temuan ke dalam dua kelompok: Fitur, serta UI/UX & Layout.
4. Urutkan berdasarkan prioritas.
5. Sertakan link referensi pada setiap temuan.
6. Perbarui `refrensi_apk.md` di root proyek dengan hasil riset.
7. Laporkan ringkasan hasilnya.

==================================================
F. FORMAT LAPORAN AKHIR
==================================================
Laporkan:

1. Jumlah aplikasi dari `apk_serupa.md` yang diriset.
2. Jumlah referensi/link yang dikumpulkan.
3. Ringkasan fitur yang disarankan (baru dan optimasi).
4. Ringkasan temuan UI/UX & Layout.
5. File yang diperbarui.
6. Catatan jika ada informasi yang belum terverifikasi.

==================================================
G. LARANGAN
==================================================

1. Jangan memakai aplikasi di luar daftar `apk_serupa.md`.
2. Jangan menyarankan fitur yang tidak bisa berjalan di mobile.
3. Jangan mengubah file selain `refrensi_apk.md`.
4. Jangan mengarang fitur, UI, UX, layout, atau link referensi.
5. Jangan mengabaikan format penulisan: wajib ada link, dikelompokkan per Fitur dan UI/UX, dijelaskan tujuannya, dan diurutkan berdasarkan prioritas.

Mulai tugas sekarang. Ikuti seluruh aturan di atas secara berurutan.
